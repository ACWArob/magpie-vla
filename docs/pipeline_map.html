PHASE 0

Session setup

once per kernel
1

Launch the driver stackcell 1

Kill any stale nodes (SIGTERM first so the UR5e releases RTDE cleanly, then SIGKILL), then spawn each driver as a child of the kernel, logging to /tmp/log_*.txt. SAM3 is a separate subprocess over a Unix socket (~90 s boot); GraspGenX serves on ZMQ.

ur5_nodegripper_node realsense2_cameraft_sensor_node SAM3 → /tmp/sam3.sockGraspGenX → :5557
⚠ VRAM budget (RTX 2070, 8 GB) SAM3 ~4.5 GB + GraspGenX ~1.8 GB + policy ~1 GB ≈ full. Stale Jupyter kernels hold ~478 MB each — kill them or the policy load OOMs.
2

ROS libs, imports, helper nodecells 2–5

Preload ROS shared libraries so rclpy imports inside VS Code, add scripts/ to the path, build the helper node: camera/depth/TCP/gripper-state/wrench subscriptions + service clients for arm moves and every gripper action.

/arm/tcp_pose/gripper/state @10 Hz /arm/move_l · /arm/stopopen/close/set_pos/set_force/clear_error
3

GO HOME + verified gripper resetGO HOME cell — run before every rollout

Release servo mode (/arm/stop — after servoL streaming the controller refuses moveL until stopped), two-stage move to the dataset home pose (vertical first, then lateral), then reboot the gripper driver: pkill + relaunch re-runs Gripper.__init__ → torque=200 written to both AX-12s, USB port reopened. Open at 16 N and read the aperture.

HOME = median frame-0 pose of the dataset verify: aperture > 80 mm
APERTURE > 80 mm“open VERIFIED” → continue to step 4
NOT OPENreboot once more → still shut = loud warning, human checks USB / servo horn
⚠ why a reboot, not “calibrate” clear_error re-enables torque at 2 N — too weak to move the fingers, so every motion after it silently stalls unless force is re-asserted. The calibrate service was just open→close (AX-12 encoders are absolute — nothing to re-zero). Rule: never command the gripper after clear_error without set_force first.
4

One scripted pickupcells 7–8, block near centre

Runs the full expert once: measures TABLE_Z from the depth cloud (feeds every z-floor), and loads the pickup namespace the collector/eval will re-run via run_cell.

TABLE_Z → z-floor = table + 231 mm gripper + 3 mm
PHASE 1

Scripted expert — the data generator

×229 episodes · 66.7/hr
5

Next grid target from the ledger

Coverage is designed, not random: 5×5 positions at 3 cm spacing × 7 angles at 15°, plus jitter (±1 cm, ±5°), extra edge repetitions, and ~15% deliberate-offset recovery episodes. The ledger (data/v1_coverage.json) makes collection resume-safe.

225 combos, serpentine orderV0 comparison: random ±4 cm → 71% one angle
6

Detect the block — SAM3

Text query → pixel-accurate mask + boxes + scores over the Unix-socket bridge. Retried if nothing scores; the episode aborts if the block truly isn’t there.

query: "red block"mask → 2D PCA / minAreaRect
7

Move above + closed-loop centering

Arm moves over the detection, then visual-servoes until the mask centroid sits under the TCP. Recording starts at the first manipulation move — the reach is training signal too.

8

Choose the grasp angle — flat-face snap

Segmented point cloud → minAreaRect on the SAM3 mask snaps the grasp perpendicular to the block’s flat face. Deterministic — this replaced the Gemini angle arbiter that caused V0’s 42/62-at-90° angle collapse.

ANGLE CONSISTENTproceed to step 9
GEOMETRIC GATE FAILSepisode tagged issue=angle → never committed (kills action divergence)
⚠ known residual: 0°/90° aliasing A square block at 0° and 90° is the same scene with two labels — slipped the mod-90 gate, taught the policy to rotate ~43° on straight blocks. Fix queued (V1.1): canonical labels + ~35 replacement episodes.
9

Re-localise AT the grasp angle

Detect again after rotating to the grasp angle, so the camera offset (frozen at scan angle) and the finger offset (rotates with the grasp) co-rotate and cancel. This killed a systematic left/right drift that flipped sides with the angle.

10

Descend + DeliGrasp close

Drop to grasp height (z-floor enforced), pre-position fingers to width + 8 mm, then DeliGrasp force closure using VLM physics priors. Up to 3 physical grip attempts — each one runs grip_refresh: clear_error → set_force → close (the 2 N trap, step 3, is why).

aperture staircase: 104 → width+8 → 20 mmgrip force ≈ 16 N
11

Slip-guarded incremental lift

Lift in steps, re-asserting grip between each (AX-12 torque dies after ~1–2 s of holding). The slip-guard node watches depth for the object dropping and reclamps.

gripper-measured width recorded (truth beats the PCD guess)
12

Recorder buffers the episode @ 10 Hz

Wrist image + 9-dim state + 7-dim declared action (the expert’s waypoint targets, not measured next-states — AWE-validated). Episode ends at lift: V0 wasted ~40% of frames on carry/place and dithered after grasping.

state = [xyz, rotvec, grip_mm, grip_force, wrist_fz] action = [target xyz, rotvec, aperture_mm]median 11.2 s (V0: 39.6 s)
13

THE REWARD GATE — the robot judges itself

Commit only if physically held (aperture band through the lift) AND the Gemini quality judge scores ≥ 0.6 (image of the grasp, temperature 0, deterministic rubric).

HELD ∧ JUDGE ≥ 0.6episode → data/lerobot_v1 (the trainable set)
EITHER FAILS→ _attempts.jsonl — auditable forever, trainable never
save rate at scale: 99.1% (231 attempts)mean reward 0.90
14

Self-reset: place at the NEXT grid target

The expert places the block at the next combo’s position and angle itself — no human between episodes. This is what makes 66.7 episodes/hour possible.

↩ back to step 5 for the next combo (225×)
15

Auto-recovery (V1.1 collector)

On a miss or crash: servo release → gripper driver reboot with verified open → home → retry the same combo. Per-episode detail goes to a log file, the screen gets one line per 10 episodes (20k output lines once froze VS Code).

RECOVERED↩ retry same combo (step 5)
3 CRASHES IN A ROW / NO BLOCKstop — block left the table; human places it back

PHASE 4

Deploy — the 10 Hz control loop

every 0.1 s tick
23

Load the policyv1_test DEPLOY cell

ACT 51.6M on CUDA with a real CPU fallback (config.device must be re-set to 'cpu' before the retry — safetensors loads to config.device). Override n_action_steps 100 → 10: execute 1 s of each predicted chunk, then re-infer. No temporal ensembling — averaging rotation vectors near 180° made rotation 3× worse in replay.

24

Arm the safety envelope

Everything the policy commands passes through this, every tick.

XY box ±10 cm of startZ ≥ table + 231 + 3 mm step ≤ 22 mm/tickEMA α=0.5 rot-rate ≤ 12°/ticktilt ≤ 25°, yaw FREE
⚠ yaw must be freeThe old total-angle cap blocked the wrist rotation the policy needs to align to rotated blocks — it caused edge grasps. Tilt-only keeps the tool upright while letting it spin.
25

TICK: observe → predict

Grab wrist image + build the 9-dim state from live topics → predict_action → take the next action: target pose + gripper aperture in mm.

26

Sanitize the motion command

In order: rotvec branch canonicalization (pick the ±2π branch nearest the current pose — kills 180°-flip lurches) → clip to XY box + Z floor → EMA smooth → step cap → rotation-rate limit → tilt gate → publish to /arm/servo_l_cmd (servo period 0.1 s; the original 2 ms bursts caused mechanical stutter).

27

Gripper: the aperture-mm mapping

The V1 policy commands the aperture directly (V0’s binary grip hid finger pre-positioning — the policy literally could not express it).

CMD < 35 mmforce-close chain: clear_error → set_force 16 N → close (async, in that order)
35–90 mmset_position(cmd) — the policy pre-positions its own fingers (observed: 86→59→55 staircase)
> 90 mm while closedopen — with set_force 16 N re-asserted between clear and open (the 2 N trap again)
only fire on >4 mm change
28

Close stall retry

2 s after a close: if the aperture is stuck > 40 mm and hasn’t moved 1.5 mm, the async clear→force race was lost — re-fire the whole chain.

SEATEDcontinue to handoff (step 29)
STILL STALLED↩ re-fire, max 3 attempts (mirrors the expert’s grip_refresh)
29

Handoff verdict — settle first, then judge

Wait until the aperture stops moving (changing > 1 mm → keep waiting, up to 8 s — “held” was once declared mid-close at 57 mm), then band-check. The held verdict is the else, never the fall-through (a slip once read “held” at 90.6 mm).

< 15 mmclosed on AIR → miss: open, no place
> 45 mmbad grip / slipped during settle → open, abort
ELSE (≈ 24–38 mm seated)HELD → hand off to step 30
aperture scale reads ~20 mm under reality: 46 mm block seats at ~27 mm
30

Scripted lift–carry–place

Policy’s job ends where the training episodes end (at lift). The script: /arm/stop (leave servo mode) → lift → carry to centre → lower → clear_error + set_force + open → rise. Same division of labour as the demos.

PHASE 5

Eval — 100 graded grasps

5×5 grid × {0°, 25°, 45°, 70°}
31

Stagehand places the blockv1_eval.ipynb, last cell

The scripted expert (phase 1 machinery, nothing recorded) puts the block at the combo’s cell + angle — or it’s already there: a clean pick (grade ≥ 0.8, yaw error < 15°) gets placed directly at the next combo’s pose, wrist-rotating the held block to the next angle. 90° is skipped as an angle: on a square block it is physically identical to 0°.

resume-safe ledger: data/v1_eval_100.json~1 min, output captured (not frozen!)
32

Policy rollout — the thing being tested

Same loop as steps 25–28, max 600 ticks (60 s — off-centre reaches creep). The arm freezes the instant the policy closes: the policy learned to lift (episodes end at lift), and its uncontrolled lift was shaking blocks loose before they could be graded.

33

Lift-verify — did it really pick it up?

Controlled 8 cm lift, then read the aperture. Success is surviving the lift, not touching the block.

12–45 mmSEATED PICK → full grading
45–70 mmEDGE/CORNER pick — held, but half credit (base 0.5)
ELSEslipped or air → FAIL, grade 0
34

Grade 0–1 + record

Base 1.0 (or 0.5 edge) − 0.1 per extra re-grip − up to 0.4 for yaw error vs the block’s placed angle (gripper is 180°-symmetric, square block 90°: error = min(d, 90−d)) − 0.2 outside the 20–40 mm seated band. Written to the JSON after every grasp — interrupt any time, resume free.

per-grasp: success · grade · edge · yaw_err · ap · tries · placed=direct|scripted
35

The failure ladder — it never grinds garbage

Distinguishes policy failures (real data) from hardware failures (pollution).

STALL FINGERPRINT (ap pinned > 85 mm, 2+ tries)hardware, not policy: gripper reboot → ↩ retry same combo, nothing recorded; 2 in a row after a verified reboot = stop
POLICY FAILrecorded → total reset (gripper reboot + home) → next combo
5 FAILS IN A ROWrelaunch the ENTIRE driver stack in place → resume
10 IN A ROWstop loudly — block off the table or physical damage; no reset fixes that
⚠ why this existsA dying gripper once recorded 36 identical “policy failures” in an hour. Hardware faults now reboot-and-retry; only real behavior reaches the ledger.
